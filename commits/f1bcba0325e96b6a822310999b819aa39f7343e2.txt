fix(elite): identity-keyed cursors, remote query, and poll serialization
- key client cursors and the ingest protocol by journal identity
  (timestamp:part) instead of the literal filename, so a .log -> .log.backup
  rotation rename never re-sends or duplicates the previous session.
- EliteRuntime.query() now reads the remote store while a client is
  connected, so elite_events/elite_search see streamed events.
- serialize client polls through a queue (as the server watcher does), so
  overlapping fs.watch/interval/startup triggers cannot duplicate lines.
- start the poll loop before the connect retry, so a first-ever outage still
  spools journal lines locally.
