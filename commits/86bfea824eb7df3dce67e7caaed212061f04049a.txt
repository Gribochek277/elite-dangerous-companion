fix(elite): explicit backfill completion signal, not first-post ack
The pending elite_backfill request was cleared on the first accepted POST that
echoed its id, so a mid-range failure lost the rest of the range, and the ack
was derived from file count, so a matched file with no complete lines left the
request re-served forever.

- the client no longer echoes the request id on data batches; it sends one
  explicit empty-files completion batch after the whole range streamed
  successfully, and skips it when a send fails so the request stays pending
  for the next connect/heartbeat
- the server clears the pending request only on that completion batch (empty
  files + echoed id), never on a data batch
- tests: a multi-file range failing part way is re-served and completes with a
  single ack; a matched file yielding no lines still acks exactly once
