fix(elite): never drop events when a journal read fails mid-plan
executeReadPlan now catches a per-instruction read failure, returns the lines
read so far with an incomplete marker and the failed identities, and leaves
the failed file's offset untouched. The active/bootstrapped cursor only
advances once every instruction in the plan succeeded, so a partial failure
never marks a file consumed or orphans a rotation drain; the next poll resumes
at the failed file. The watcher surfaces incomplete reads through onError,
which the runtime now counts and logs instead of ignoring.
