fix(elite): backfill window, remote presence/status, and spool crash safety
- client backfill now records out-of-window files as consumed so the first
  poll no longer streams the whole pre-window history as deltas.
- currentSnapshot returns the remote store while a client is connected, so
  elite_presence and the elite_crew section stop reporting out_of_game.
- the ingest protocol carries a Status.json snapshot; the client sends it on
  change and the server routes it to store.applyStatus, keeping remote
  GameState (fuel/cargo/credits/docked) in lockstep with local.
- pollJournals/backfill spool (or send) lines before persisting the offset,
  and loadSpool keeps valid records while dropping only damaged lines, so a
  crash mid-poll can never lose events.
